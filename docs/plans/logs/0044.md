1. **defect.** `crates/vxe-audio/src/mixer.rs:482` (`retire`), also `:487` and `:501`. If the
   retire channel and the hold are both full, or the `Recycler` is gone, the callback drops
   what it retires, and that can include a voice's `VoiceBuffers`. The callback then frees
   memory, and the pool loses that voice for good. Reproduced on a scratch crate (not

## Fix pass (side-lane review findings 1, 2, 3)

### Finding 1: retire never drops a voice's buffers

- Mechanism (`mixer.rs` module comment): retired voices wait in a voice hold of `MAX_VOICES`
  slots that cannot overflow (64 buffer sets, each in one place), flushed before a separate
  source hold of `MAX_VOICES`; a dropped `Play` past the source hold still drops its source on
  the callback (a free only if it carried the last reference). With the `Recycler` dropped,
  buffers go to a `dirty` store on the mixer and are cleared when a `Play` takes them.
- `tests/mixer.rs::a_burst_past_every_hold_keeps_every_voice_buffer_and_frees_nothing` (64
  looping voices, then 200 `Play`s and 64 `Stop`s in one block, 4 recycle-and-render rounds,
  64 new `Play`s): on the old `mixer.rs` it fails with 128 frees on the callback (64 voices x
  2 buffers); with the fix 0 frees and 64 voices.
- `tests/mixer.rs::a_dropped_recycler_keeps_every_voice_buffer_on_the_mixer`: old code, round
  2 starts 0 voices of 64; fixed, 64.
- `tests/output_hash.rs::a_fixed_scene_renders_to_a_pinned_hash` (900 blocks, HRTF, default
