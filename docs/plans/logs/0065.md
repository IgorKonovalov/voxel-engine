## Phase 2: the temporal pass reads the store plainly

Start commit: `cc5b55d`.

**Names in the tree:** the override is `COUNT_STORE` in `temporal.wgsl`; the counters are
`counters` (group 2 binding 12, `array<atomic<u32>, 3>`), a 12-byte buffer of the frame's
(`Frame::store_counters`), bound in both pipelines and written only by the one built with
`COUNT_STORE` true (`Frame::temporal_counting`, built on its first counting encode). The switch
is `Frame::set_count_store(bool)` / `Frame::counts_store()`, off by default; the fly-through sets
it each frame to `HUD shown || --read-missing`. `read_store_stats`, `copy_store_stats` and
`try_store_stats` read the counter buffer; the store's words 0 to 2 are left unused (the layout is
unchanged). The store binds `var<storage, read> store: array<u32>`; its origin, size and cell
shift load once a pixel (`StoreHead`, `store_head()`).

- **The early-out's condition and age:** a store's pixel with `LIGHTING_LAMP` clear, no
  `FLAG_CUTAWAY` and not the steps view (the light pass writes a lamp part in the cutaway and
  counts in the steps view). It writes `(value, 0)` and moments `(0, 0, age, 1)`, the age being
  last frame's moments' age at the same pixel plus one (capped at `AGE_MAX`), 0 with no history or
  inside an edit box: one texture load in place of the reprojection.
- **The counts at the start commit:** `the_store_counters_count_with_the_override_on`'s frame read
  `[366, 658, 0]` (missing, brick reads, coarse reads) on lavapipe at `cc5b55d` (the renderer of
