### What `--pre-roll` does beside `--near 0 --coarse 0` (Plan 0109's W3)

Not the same arm in any value. From the code (`run/loading.rs`, `Args::full_first`,
`Frame::set_bake_coarse`):

| | pre-roll's near list | pre-roll's end | live queue after frame 0 |
|---|---|---|---|
| `--pre-roll full` (default) | 125 chunks (`--near 2`) | coarse pass passed, or its 5 s box | near 2, coarse 256, full-first 2 |
| `--pre-roll near` | 125 chunks | the step after the near chunks' moment (box 0 ms) | **unchanged**: near 2, coarse 256, full-first 2 |
| `--pre-roll off` | none | its second step | **unchanged** |
| W3, `--near 0 --coarse 0` | 1 chunk (the camera's) | at the near chunks' moment (`coarse` 0) | near 0, **no coarse pass**, full-first 0 |

So `near` keeps the near shell's light at frame 0 and changes nothing after it; W3 holds one
chunk and changes the queue for the whole run (no coarse blocks; the full count beyond the
camera's chunk waits its turn). `off` holds the fewest chunks of the four but keeps the coarse
pass. Read on the RTX (forest, hall; three starts each, same host, load 5.3 to 5.7, release,
thread on, `--frames 8`): W3 forest first frame 927 / 959 / 1074 ms, pre-roll 17 to 19 steps, 4
chunks baked; hall 616 / 617 / 642 ms, 2 steps, 7 chunks baked; `first frame light:` not read
in 8 frames in any of the six.
