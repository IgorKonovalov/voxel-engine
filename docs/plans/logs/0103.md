# Driver disk cache vs. Plan 0103: is the second start warm? (2026-11-24)

Tree: main a824f97d, release `flythrough`. Every run:
`flythrough --headless --source outdoor --path outdoor --frames 30 --report <dir>`, plus
`--adapter RTX` (RTX 3080 Laptop, NVIDIA 615.78.08, Vulkan) or
`--adapter RENOIR --profile portable --render 1280x720` (Radeon Cezanne iGPU, RADV, Mesa 26.2.5).
Loading screen off (the headless default). No engine-side pipeline cache: the fly-through sets
none (`debug::set_pipeline_cache` is used only by the vxe-render test support), so no
engine-warm pair could be taken without building something.

Each group held the perf lock exclusively (one `flock` per triple or pair), inside a 16 GiB
scope. 1-minute load 3.4 to 7.3 for every run (a second lane was running): **loaded, indicative**.
Power on AC. Runner: `live/pc-run.sh`, `live/pc-seq.sh`; raw logs and `run.json` per run under
`live/pc/<run>/`; table from `live/pc-table.py`.

Columns: seconds since process start, from the `diag:` lines and `run.json`.
- device: `device ready after`.
- frame: `diag: frame created` (the frame's own pipelines and targets).
- pipes done: `diag: entity pipelines built` (the last pipeline of the build worker).
- **span**: pipes done minus device ready: all start-up pipeline creation, plus target
  allocation and the 3 GB mirror reservation (about 0.09 s).
- stage: `run.json` `load_stages` "building the pipelines" (the part after the mirror's creation:
  entity and bake pipelines).
- pre-roll: the two light pre-roll stages (near + coarse), mostly light baking.
- **first**: `first frame after` (process start to the first world frame).

## How the variables were verified

- NVIDIA `__GL_SHADER_DISK_CACHE_PATH` (+ `__GL_SHADER_DISK_CACHE=1`,
  `__GL_SHADER_DISK_CACHE_SKIP_CLEANUP=1`): after each cold run a `GLCache/<id>/<id>/*.bin` +
  `.toc` pair (2.92 MB) appeared in the scratch dir, and the next run was warm.
  `__GL_SHADER_DISK_CACHE=0`: the off pair reads the same as an empty cache (36 s).
  `__GL_SHADER_DISK_CACHE_SIZE=1000000` (no SKIP_CLEANUP): the first run's file stopped at
  1.00 MB, and the second run was only partly warm (24.2 s of 35 s). The file reached 2.00 MB
  after it, so the limit is not exact.
- Mesa `MESA_SHADER_CACHE_DIR`: `mesa_shader_cache/` (index + part0..49) and
  `radv_builtin_shaders` appeared, 182 files, 4.87 MB, unchanged by the warm runs.
  `MESA_SHADER_CACHE_DISABLE=true`: the off pair reads the same as an empty cache (10.5 to 11.4 s).
- The owner's real caches (`~/.cache/nvidia`, 715 MB; `~/.cache/mesa_shader_cache`, 196 MB;
  `~/.nv`) were not read or touched.

## Findings

- **RTX:** the driver cache makes the second start warm. Pipeline span 35.5 to 36.7 s cold,
  0.36 to 0.51 s driver-warm (the pipeline stage itself 0.09 to 0.15 s). First world frame
  46 s cold, 6.5 to 9.5 s warm. The Plan 0094 engine-cache figure is 0.24 s warm against
  29.4 s cold, read in a different scope (`gpu_frame`: a frame and its entity pipelines only).
  The driver-warm span is within about 0.1 to 0.3 s of it, and part of that span is target
  allocation and the mirror reservation, not pipelines.
- **Radeon (RADV):** the same. Span 11.7 to 12.4 s cold, 0.48 to 0.54 s driver-warm (stage
  0.07 to 0.10 s). First frame 19.6 to 20.3 s cold, 6.8 to 7.1 s warm. No engine-cache warm
  figure exists for RADV.
- **Over the limit, NVIDIA:** a cache capped below the run's needs leaves the second start
  about 2/3 cold (24 s span, 33 s first frame). This is the failure that raised the plan: with
  a healthy driver cache the plan gains about 0.1 to 0.3 s per start. It pays only when the
  driver cache fails (size limit, a cleared cache, a driver update), or on drivers without a
  disk cache.
- **Once warm, the first frame waits on the light pre-roll:** 5.7 to 7.0 s of the warm 6.5 to
  9.5 s on both adapters. The pre-roll is also about 2.5 s longer cold than warm on the RTX: a
  cold run's longest pre-roll step is 1253 ms against about 50 ms warm, so some pipeline or
  shader work seems to land in the pre-roll on a cold start.
- **Default-off arms:** a default start builds none. `load_stages` has no "building the light
  pass arms" stage (that stage runs only when the start settings pick an arm), so default-off
  arms cost 0 s of this cold time. The stages do not break the cost down by arm any further.
- The NVIDIA cache file grows by 40 to 120 KB on each warm run, so a few pipelines are new on
  each run (unexplained, small). The RADV cache does not change size.
